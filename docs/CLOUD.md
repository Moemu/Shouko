# 全连接组端到端控制 · 云端实验

已跑通感觉输入 → 完整连接组 → 12 个关节动作的端到端训练与独立行走验证。云端运行真实物理与神经计算，本机以 VRM 美少女角色显示实测关节状态。

身体使用 G1 的 12 关节物理代理，保留其质量和惯性，用基本几何体计算平地接触。角色骨骼跟随关节角，上肢显示跟随下肢；这不是按角色外形重新建立的人体肌肉模型。

## 连接组与模型

保留 MaleCNS v1.0 导入的 166700 个神经元与 25582938 条神经元间连接。不再抽取 8192 子图。连接方向为 `W[post, pre]`。

人工身体观测经可训练编码器进入数据标注的感觉神经元。读出使用标注的 VNC / CB 运动神经元，直接输出 12 个关节动作。关节 PD 是执行器控制，不是预训练行走策略。

所有实测连接拥有可训练增益，保持初始符号。神经元偏置、感觉编码和运动输出共同训练。采用人为指定的活动率动力学；每次决策展开 4 次神经更新，不模拟生物脉冲或完整生理时间尺度。目前每次决策重新初始化活动状态，上一动作作为身体观测的一部分。

共有 26,575,852 个可训练参数。检查确认各参数组都收到非零梯度；最终约 81.9% 的连接增益发生变化。保留所有连接不表示每一条边都从本任务获得了有效梯度。

## 训练方式

首先用已有 G1 策略提供动作示范，通过反向传播训练完整控制路径。随后采集学生动作导致的身体状态，再由教师标注关节动作，迭代训练（DAgger）。教师只用于训练与物理基准校验。

独立评估与实时预览不加载教师，由果蝇连接组策略直接控制关节。这次采用监督模仿与 DAgger，尚未实现 PPO 等基于奖励的强化学习；不能将本结果表述为从随机动作纯强化学习得到行走。

## 复现

云实例复用基础 PyTorch 2.12.1+cu130。主要运行时及额外依赖锁定在 `requirements.cloud.lock.txt`；不要使用本地 CPU 原型的安装脚本覆盖云环境。新环境可用 `python -m venv .venv` 和 `.venv/bin/python -m pip install -r requirements.cloud.lock.txt` 安装，另需本文记录的数据及 Unitree 资源。

```bash
cd /root/autodl-tmp/neuromechfly
.venv/bin/python -m app.launch_cloud train --seconds 600
.venv/bin/python -m app.evaluate_full
.venv/bin/python -m app.check_full
```

等训练进程结束再运行验收。续训默认从已有权重开始，重新初始化 Adam 状态。验收脚本不会训练或选择检查点。`app.select_full` 是本次比较早期与转向候选的辅助脚本，使用训练验证种子。

Windows 端使用 `./cloud.ps1 Preview` 恢复隧道与预览，`./cloud.ps1 Status` 查看状态。SSH 目标用 `-CloudHost user@host -CloudPort 12345` 传入，或一次性写入 `runs/cloud/target.json`（git-ignored），格式 `{"host": "user@host", "port": "12345"}`。训练有时间上限；预览保持在线时实例继续计费。停止训练不会自动关闭整个云实例。
