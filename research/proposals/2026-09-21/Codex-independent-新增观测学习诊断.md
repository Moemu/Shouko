# 新增 vx/vy/height 观测学习诊断

日期：2026-09-21

提出方：Codex independent

范围：只审查当前生产代码和 `runs/yumi_calibration_20260921/` 实测数据。

## 独立声明

本提案未参考同日其他提案，也未采用其他 Agent 的结论。结论只来自代码、检查点、PPO 日志和观测探针结果。

## 结论

50 维观测已经接入策略。当前影响很小的现象已经复现，但现有证据不能给原因排序。输入尺度和零初始化是候选假设之一，不是已确认的首要原因。

现有证据可以排除两种较窄的解释：`GPUHumanoid` 没有传入新列，以及 PPO 没有创建或执行包含 encoder 的 actor 优化组。它不能证明新增列获得了有效的学习更新，也不能证明新列不能改变运动，更不能由固定输入的动作 RMS 推断视频中的身体结果。

扩维脚本把新增三列初始化为：

- `encoder.weight[:, 47:50] = 0`；
- `obs_mean[47:50] = 0`；
- `obs_std[47:50] = 1`。

这保持了旧 47 维策略的初始行为，也使新信号在初始前向传播中的数值尺度较小。实际新增观测的标准差只有 `0.0812、0.0643、0.0414`。因此，使用 `obs_std=1` 时，经过策略标准化层的新增列仍只有约 `0.04–0.08` 的量级。旧观测的 `obs_std` 多数由采样数据得到，范围约为 `0.05–1.08`。这是输入尺度事实，不是训练因果结论；Adam 会部分抵消梯度尺度变化，不能据此预测权重应增长多少。

PPO 路径不会重新估计观测统计量。`set_observation_stats()` 只在 `train_full.py` 的模仿学习路径调用。PPO 直接加载检查点中的 `obs_mean/obs_std`。这是一项已确认的流程事实，不应直接称为缺陷：新统计量若用于 PPO，会同时改变 actor 和 value 的输入。

## 证据

### 1. 观测线路正确

`app/gpu_body.py:120-130` 先构造原有 47 维字段，再追加：

- `qvel[:, 0:2] * linear_velocity_scale`；
- `qpos[:, 2] - height_reference`。

`app/full_brain.py:72-76` 对 50 维输入执行标准化，并把全部输入送进 `encoder`。没有发现切片仍为 47 维、维度错位或新列未进入前向传播的问题。

`runs/yumi_calibration_20260921/rollout.pt` 中新增字段的实测统计为：

| 字段 | 均值 | 标准差 |
| --- | ---: | ---: |
| vx | 0.0473 | 0.0812 |
| vy | -0.0045 | 0.0643 |
| height | -0.0475 | 0.0414 |

同一批数据中，新增字段与即时奖励的相关系数为 vx=`0.518`、vy=`0.438`、height=`0.287`。这显示轨迹中存在统计关联。与 GAE advantage 的相关系数只有 vx=`-0.077`、vy=`0.186`、height=`0.150`。这提出“策略梯度信号较弱”的候选解释；相关系数不构成因果证明。具体数值和输入文件哈希保存在 `runs/yumi_input_audit_20260921/independent_statistics.json`。

### 2. 固定输入敏感度是观察结果，不是运动结论

`app/expand_observation.py:36-38` 明确使用零权重和 `0/1` 统计量扩维。源检查点的旧 encoder 权重 RMS 为约 `0.1313`，新增三列完全为零，新增统计量为 `obs_mean=0`、`obs_std=1`。

固定输入探针 `runs/yumi_calibration_20260921/sensor_probe.json` 给出：

| 检查点 | 新 encoder RMS | vx 一标准差造成的动作 RMS 变化 | vy | height |
| --- | ---: | ---: | ---: | ---: |
| 源 best | 0 | `1.24e-7` | `1.28e-7` | `1.19e-7` |
| normalizer fix 之后 | `3.20e-4` | `3.21e-5` | `4.34e-5` | `4.49e-6` |
| 低学习率版本 | `9.37e-5` | `6.07e-6` | `1.03e-5` | `3.79e-6` |

同一探针批次中的动作 RMS 约为 `1.239`。这些数字只描述固定策略、固定输入批次和单列干预下的动作敏感度。MuJoCo 后续动力学是非线性的，不能据此断言新增列不能改变身体运动，也不能直接解释视频结果。它们只说明当前检查点还没有表现出明显的局部动作敏感度。

### 3. PPO 优化器确实执行了更新

两个短训日志都写出：

```text
"policy_optimizer": true, "optimizer_state_skipped": null
```

`app/ppo_yumi.py:176-189` 按参数名和形状恢复状态，`app/train_full.py:62-83` 对不匹配状态会返回失败。当前两次短训都执行了策略更新：

- normalizer fix：307 个策略优化步，157184 个策略样本；
- 低学习率：768 个策略优化步，393216 个策略样本。

因此，当前证据不能把“encoder 没有加入 optimizer”作为解释。需要注意，源 `ppo_state_best.pt` 的 Adam policy state 为空；代码仍成功恢复参数组结构，但没有历史 policy 动量。这可能影响热启动的优化器动力学，仍需单独控制，不能直接排除为影响因素。

### 4. 学习率和 KL 提前停止是待控制因素

normalizer fix 使用 encoder 学习率 `2.5e-5`，且 6 个 actor 迭代中有多次在 2 到 104 个 minibatch 后因 KL 提前停止。低学习率版本的 encoder 学习率只有 `2.5e-6`，虽然完成了 768 个策略优化步，新增列 RMS 反而只有 `9.37e-5`。

这两个结果不能证明某个学习率更好，也不能从 encoder RMS 的变化反推梯度被输入尺度等比例压小。Adam 的归一化会部分抵消梯度倍数。应记录新列的梯度范数、Adam 后参数增量和动作敏感度，再讨论学习率或 KL 的作用。

## 已确认与未确认的问题

### 已确认

1. 50 维观测从物理环境进入策略。
2. 扩维后的新增权重为零，新增 `obs_std` 为一。
3. PPO 没有使用轨迹重新估计新增观测统计量。
4. PPO 策略 optimizer 被创建并执行，state 恢复没有被形状检查拒绝。
5. 当前新增 encoder 权重和固定输入动作敏感度都很小；这不是运动结果。

### 尚未确认

1. 校准 `obs_std` 是否足以提升行走结果。
2. 新增观测是否能解决低速命令下的推进不足。
3. 新增观测在固定连接组上是否存在足够稳定的 credit assignment。
4. `LayerNorm`、冻结边、GAE 重尾回报和 KL 门控各自占多大影响。
5. 共享 `obs_std` 改动对 critic 的影响是否会混入 actor 比较。

## 最小可证伪实验

先做一个控制 critic 混杂的 actor-only A/B 实验。保持源检查点、随机种子、world 数、PPO 超参数、评估种子和训练步数完全一致。

### A：当前协议

- 新列权重为零；
- 新列 `obs_mean=0`、`obs_std=1`；
- 复现已有 3 次短训屏幕，记录 encoder RMS、动作敏感度、每个速度档均速和跌倒数。

### B：只校准 actor 的新增列

- 保持旧 47 列完全不变；
- 将新增 `obs_std` 设为固定训练轨迹统计量，并应用现有 `clamp_min(0.05)` 规则；建议为 `[0.0812, 0.0643, 0.05]`；
- 新列 `obs_mean` 先保持零，因为 vx、vy 和相对高度的物理零点有明确含义；
- 保持新增 encoder 列零初始化。

这里不能直接改 `policy.obs_std` 后运行现有 PPO。`ppo_yumi.py` 在 actor 和 value 两处都使用这个 buffer：`policy(obs)` 在 actor 内部标准化，`value((obs - policy.obs_mean) / policy.obs_std)` 在 critic 路径再次使用。同目录 CPU 审计 `runs/yumi_input_audit_20260921/statistics.json` 已记录，naive shared scale 会使 value MSE 从 `326.115` 变为 `111918.806`。因此，直接修改共享 scale 的 A/B 不是只测试 actor。

推荐的无生产代码控制方式是使用一次性实验 wrapper：actor 使用 B 的新尺度，critic 始终使用 A 的原始 `obs_mean/obs_std`。若实验框架必须修改共享 buffer，则同步克隆并重参数化 `Value.net[0].weight[:,47:50]`，按新旧 scale 比例变换，并在 CPU 上验证 value 预测误差；现有记录显示解析补偿后的最大绝对误差为 `6.1e-5`。还要明确处理 value optimizer state，或重置该 state；仅补偿第一层权重不等于整个 on-policy critic 训练等价。

零初始化保证 A 与 B 的初始 actor 前向相同。若 B 在 3–7 次策略迭代后同时出现以下现象，只能支持“输入尺度值得继续测试”，不能直接判定它是主因：

- 新列的梯度范数或 Adam 后参数增量与 A 有可重复差异；不要预设新 encoder RMS 必须增长 10 倍，Adam 会近似抵消输入梯度倍数；
- 固定一标准差扰动的动作 RMS 同步变化；
- 低速档均速或传递斜率在重复评估中有一致改善。

若 B 只改变局部权重或动作敏感度，却没有改善速度档表现，则不能据此宣布尺度问题成立，仍需检查新增观测的 RL credit assignment、奖励设计和固定连接组限制。若 B 的梯度、参数增量和动作敏感度都与 A 相同，再测试 C：只提高 encoder 新列的学习率，其他组、critic 输入和输入统计量保持不变。C 仍无差异时，才有理由提高对 advantage 信号或冻结连接组限制的怀疑。

## 执行边界

不要直接把校准后的 checkpoint 覆盖生产 `best.pt`。每个候选应写入独立实验目录，并保留检查点和 PPO state 的 SHA-256。三次重复应使用配对评估；单次得分只能用于监控，不能据此启动长训。

本提案建议先完成控制 critic 混杂的 A/B 短训和固定输入探针，再决定是否进行完整训练。若 B 未带来可重复的低速推进改善，应暂停“继续延长同一 PPO 配方”的计划，改讨论奖励塑形或连接组可训练范围。

## 审查补记（2026-09-21）

审查后撤回“输入尺度是首要原因”“已确认设计缺口”和“当前输入不能改变运动”的强断言。正确表述是：扩维初始化和统计量选择形成了可检验的尺度假设；critic 与 actor 共用 `obs_std`，所以简单的共享 scale A/B 会改变 value 输入，必须隔离或解析补偿。

本补记也撤回“新 encoder RMS 应按输入尺度成倍增长”的隐含预期。Adam 的一阶、二阶矩归一化会让参数步长对梯度整体缩放近似不敏感。后续实验应记录梯度、参数增量、策略敏感度和身体评估四类指标，不预设其中任何一个按固定倍数变化。
