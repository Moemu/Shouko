# 路线可靠性复核与条件式继续建议

日期：2026-09-23。

本文是综合评审，已阅读原会话、2026-09-22 最终决策、Codex-independent、Qoder、ZCode 的相关提案。本文不声称盲审。数据结论重新对照代码、原始 JSON、现存权重哈希和历史步态序列。独立盲审另存同目录，避免把多篇相互引用的意见当成多份独立证据。

本次只新增评审文档。未修改训练、评估、预览代码或权重；未训练、重跑物理或操作云实例。原有未提交文件保持原样。下文方案供用户定稿，不是已执行实验。

## 判断

**有条件继续项目；局部调整训练和验收方法；目前不支持推翻连接组、Yumi 或工程框架。现有证据也不足以确认冻结连接组加当前 PPO 配方能够学成自然直立行走。**

原最终提案作为“停止盲训、控制投入”的决策较可靠。作为“初态朝向课程是最值得优先投入的修复”的论证，只具有中等支持。作为当前目标可行性的证明，证据不足。

| 判断层 | 可靠程度 | 原因 |
|---|---|---|
| 当前表现和主要数字 | 高，限于记录的权重与评估条件 | 27 初态原始记录复算与汇总一致 |
| 不晋升 B、不原样长训 | 高 | 成功增加伴随横漂恶化；只有一个训练种子 |
| 保留现有工程与身体 | 较高 | 有历史控制成功记录；未发现必须重写工程的证据 |
| 初态覆盖是主要瓶颈 | 未证实 | 表现、命令敏感度与根因是不同问题 |
| 小角度恢复课程应先于所有方法基线 | 中等偏弱 | 成本可控，但诊断信息有限，且课程暴露频率未定义 |
| 当前架构必能完成自然直立行走 | 不确定 | 无同任务成功基线；验收尚不能充分识别自然步态 |

这些等级是证据强度判断，不是统计概率。

## 2. 原方案遗漏了比朝向更上层的验收问题

用户目标是正常行走。现有六判据主要识别不倒、推进和交替接触，不充分识别自然步态。

`app/evaluate_full.py:59-65` 与诊断 `native_feedback.py:60-66` 中：

- direction 只检查终点横移，没有约束全过程最大横移、累计横向误差或偏航；先偏离再返回可以被终点量掩盖。
- upright 衡量躯干倾斜，不等于膝部自然伸展或骨盆足够高。
- feet 和 alternation 只有触地次数下限，没有接触事件去抖、摆动持续时间或足底滑移约束。

本轮重跑了已存数据的 `runs/local/gait_measure_20260918/analyze_bouts.py`，没有重跑物理。cmd=0.5、seed=8001 的历史记录中：

| 世系 | 30 秒左右接触段数 | 接触段中位时长 | 相邻接触段空隙中位时长 |
|---|---|---|---|
| 直立祖先 `666134f2…` | 141 / 125 | 0.12 s | 0.06 s |
| 深蹲 `a7a4281f…` | 154 / 129 | 0.12 s | 0.06 s |

原始文件为 `gait_tall_frames.npz` / `gait_squat_frames.npz`；JSON 中亦保留接触频率、膝角、支撑占比等量。此结果说明交替计数很容易被短周期接触切换满足。不能仅凭该计数认定存在正常摆动步态。

边界：这些详细序列属于旧世系，不是新 obs50 权重的逐帧诊断。不能直接宣布新权重步态完全相同。但当前 120 秒记录仍有 544/498 次触地，足以要求复测步态质量，而非默认该问题已解决。历史脚本的 lift/bout 定义也不等于严格的摆动期最大离地高度，不宜直接用作新验收阈值。

**推断：只修朝向可能得到更直的拖步。** 因此先定义可测的正常步态要求，比立刻选择“删换脚奖励还是加朝向初态”更重要。建议报告足底滑移、有效摆动时间及离地高度、左右步态差异、姿态和路径误差；先审查实测分布，再预登记合理阈值，不臆造统一的人体步频标准。

## 3. 小角度恢复课程合理，但协议尚不完整

`app/gpu_body.py:102-112` 的 reset 不随机 yaw。这证明初始姿态覆盖不足，不证明策略训练期间从未见过非零 yaw。闭环漂移本身就会产生偏航状态。

更关键的是 `app/ppo_yumi.py:286-296,312-373`：环境在启动时重置，随后只在 fallen 时重置；没有按恢复课程固定时长结束回合。128 steps 约为 2.56 秒采样块，不是每 2.56 秒重采初态。

因此，把 yaw 扰动加进 reset，不等于 20 轮 actor 更新都在反复练习恢复。存活策略可能只接触一次指定初态，之后采样大量已偏离或已恢复的状态。只改变 reset 而未记录实际恢复机会，阴性结果很难解释。

建议先定义恢复课程的暴露协议：按速度、偏航符号、幅度分层，记录实际启动次数、恢复成功率、恢复时间及失败状态。若引入固定回合时长，控制和实验组必须使用相同规则；把它明确记为共同协议变更，并正确处理时间截断的 value bootstrap，不能混成跌倒终止。

还需保留两个区别：

1. 恢复 yaw 到零不等于回到原路径。横向误差已经形成时，即便朝向修好，终点横移仍可能失败。应分别量恢复时间、恢复后的横向漂移率及整段路径误差。
2. 小偏差课程可以预防大偏差；不能仅因 ±0.2 小于失败轨迹的最大 yaw 就认定课程无效。反之，20 轮未见收益也不能否定所有课程学习。

原门槛“两个种子各成功 +6/27、方向 +5/27”可以作为追加预算的严格条件，但不是统计证明或架构否定线。应同时展示每个种子的配对连续量和各速度档，记录受益与退化回合。两个续训种子也不等于两个独立从头训练的模型。

## 4. 对其他提案的取舍与纠错

| 提案 | 采纳部分 | 不采纳或需限定部分 |
|---|---|---|
| 原 Codex 最终稿 | 不盲训、不靠 score 晋升、哈希绑定、单变量、最终留出 | 课程前置尚非因果结论；教师基线不应无限后置；自然步态验收缺项 |
| Codex-independent 奖励审计 | 区分代码事实与奖励因果；记忆重置不直接等于 bug | 固定权重突然 carry state 只能诊断即插即用效果，不能评判记忆训练的价值 |
| Qoder | 提前做奖励贡献记录及小策略基线，有较高诊断价值 | “提高 gain 去饱和”“短训失败即证伪课程”“小策略失败即归因身体”均过强 |
| ZCode | 门槛过严可漏掉中等收益；短训阴性不能推翻路线 | 奖励导数论证及参数规模引用需纠正；教师基线触发不必依赖两轮阴性 |

具体纠错如下。

**奖励曲线不是 PPO 的直接反向传播路径。** `ppo_yumi.py:312-378` 在 no_grad 中采样、计算奖励与 GAE；`413-425` 对 log-prob 比率和优势形成的 surrogate loss 求导。因此 `d reward / d yaw` 变小可以提示远离目标时回报区分度下降，但不能直接证明 actor“没有拉回梯度”。应看完整轨迹的回报差、优势信号、探索覆盖与策略更新。[PPO 原论文](https://arxiv.org/abs/1707.06347)

数学上也不支持 Qoder 的“超过约 0.5 rad 就几乎没有信号”：对 `0.8 exp(-3 yaw²)`，在 0.5 rad 的导数绝对值约 1.134，约为最大值 1.189 的 95%。这些是解析复算，不是实验结果。只有更大角度时该曲线才显著变平。各回合 mean_abs_yaw 也不能直接告诉我们多少采样时间落在某区间。

**增益和限幅不能混称为去饱和。** `clip(-k*yaw, ±cap)` 的饱和阈值是 `cap/k`。现值为 0.2/1.4≈0.143 rad。固定 cap 时增加 k 会更早饱和；增加 cap 才扩大线性区，但同时改变训练命令分布。

**节律不能直接归功于果蝇连接组天然 CPG。** 当前 `full_brain.py:72-85` 每次默认清空神经状态，环境还输入显式 sin/cos 相位和上一动作。没有消融证据区分身体反馈、外部时钟、已有训练权重与拓扑的贡献。

**可训练参数不是约 21 万。** 据 `data/full_graph.json` 和 `full_brain.py:60-65`，50 维策略冻结核心后，bias、encoder、readout 合计为 `166700 + 17336×50 + 815×12 + 12 = 1,043,292`。另有 12 个 log_std 参数，critic 单计。ZCode 引用了代码中的过时注释；参数量本身也不能证明容量充足或不足。

此外，`Codex-independent-可复现评估后的路线选择.md` 的 source 分速度表不对应完整 27 条原始记录。本轮复算三个速度档的世界前向均速为 0.03787 / 0.10127 / 0.25037 m/s，各档九条；平均横移为 2.39065 / 4.27034 / 5.15415 m。原最终稿的总计表正确。后续应引用原始 JSON 汇总，不继续传播该分组表。

## 5. 参考项目能支持什么

**NeuroMechFly / FlyGym：** 官方 hybrid controller 使用 CPG、预编程步态及局部回撤和绊倒纠正。它支持把不同控制职责分开，并用行为测试比较；它不是完整连接组直接学成人形行走的证据。即便官方 FlyBody 集成教程也保留混合控制器，而不是加载完整果蝇脑。本文不建议直接搬入该控制器，因为那会改变本项目最终关节控制必须来自连接组的边界。[混合控制器](https://neuromechfly.org/tutorials/4c_hybrid_controller/)；[FlyBody 集成](https://neuromechfly.org/tutorials/5b_using_flybody_model/)

**FlyBody：** 官方项目提供细致的果蝇 MuJoCo 身体、walking imitation 环境和 RL 训练入口。对本项目最有用的是先建立身体特定的运动能力与行为参照，再研究神经控制。迁移这个实验方法是合理推断，不是它已经验证了 Yumi 或连接组蒸馏。[官方仓库](https://github.com/TuragaLab/flybody)

**Unitree RL Gym：** 本地固定版本 `vendor/unitree_rl_gym/legged_gym/envs/base/legged_robot.py:281-305,693-701` 明确区分 heading→角速度命令以及角速度跟踪奖励，并周期性重采命令；G1 配置启用 tracking_ang_vel。当前项目只有朝向反馈输入和 yaw 奖励，没有同样的角速度跟踪契约。借鉴点是命令、观测、奖励与验收一致，不能把 G1 权重直接迁移失败等同 Yumi 无法学习。[官方仓库](https://github.com/unitreerobotics/unitree_rl_gym)

**FlyCube：** 使用教师监督和课程训练，并清楚区分策略与搜索；公开旧结果还有反向连接版本边界。其游戏结果不能证明生物拓扑天然擅长双足控制，但支持“训练期教师、运行期独立学生”的工程思路。[官方仓库](https://github.com/lntegrals/flycube-public)

以上参考均不能推出“增加更多生物细节、改 LIF 或换整个仿真平台就能解决”。当前最缺的是同目标、同身体的可达性基线。

## 6. 我建议的执行次序

**第一步：把目标和比较口径固定下来。** 将 ordered CSR 原生评估整理为复用入口，绑定 checkpoint、graph、身体 XML、完整接口、后端、batch 与版本。保留历史六判据作回归，增加路径和步态质量报告。重测旧深蹲与当前直立权重时保留各自正确接口，明确这是历史能力参照，不是单变量因果实验。

同时记录来源轨迹的各奖励项、优势分布、有效更新量及按速度/偏航分组的表现。奖励绝对占比只是诊断线索，不等于策略梯度贡献；不能仅因某项总和大就删除它。

**第二步：保留有界恢复课程，同时提前建立小型 MLP 诊断基线。** 不必在一张 GPU 上同时跑三个训练进程。可以同批次设计、顺序执行，各自锁定输入、身体、动作接口、任务、评价和预算。

课程对照补齐恢复机会分配后，先判断是否真正学到双向恢复及其对推进的作用。原工程门槛可用于决定是否追加预算，但应将“未过门槛”与“没有任何可信改善”分开。

MLP 基线先复用相同观测和动作接口，避免同时加入 LSTM、特权观测和新奖励，使失败原因更难解释。分别报告环境样本量、优化更新量和墙钟预算；同墙钟比较回答工程效率，同样本比较回答学习效率，均不等于容量测定。对从头 MLP 与预训练连接组的不同起点也需明确记录。

**第三步：按结果选择方法，而非强行得出二选一结论。**

| 新证据 | 能支持的结论 | 下一步 |
|---|---|---|
| 恢复课程稳定改善方向、推进且姿态/步态不退化 | 当前接口下存在可学改进 | 小步扩大课程，最终用新初态验收 |
| MLP 达到同任务要求，连接组 PPO 仍停滞 | 当前连接组训练路径值得调整；身体并非唯一障碍 | 优先教师动作拟合，再做学生闭环 DAgger/蒸馏 |
| 学生离线拟合良好，闭环失败 | 更像分布偏移或反馈误差累积 | 优先交互数据和恢复轨迹，不立即改网络容量 |
| MLP 达标，学生在覆盖充分的监督数据上仍拟合差 | 接口、优化或表示限制得到更强支持 | 逐项比较编码/读出、可训练边集合或内部展开等局部结构 |
| 两者短预算都失败 | 仍然证据不足 | 先核查预算充分性、优化和任务定义，不能宣布身体不可行 |
| 速度/方向改善但仍是拖步 | 当前行走评分有收益，用户目标未完成 | 转向有步态参照的训练或可测的摆动/滑移约束 |

教师只用于训练和诊断。最终连接组仍直接输出关节动作。先做有监督拟合再做闭环学生测试，比“PPO 失败所以容量不足”的推理更能区分原因。

重构训练方法的证据门槛应低于重写工程框架的门槛。现阶段可投入验收整合、同任务基线和可归因实验；不应因为有多篇模型提案持相近意见，就升级为大规模架构重写。

## 7. 独立盲审的交叉意见

同目录 [Codex-audit-independent-代码与实测盲审](Codex-audit-independent-代码与实测盲审.md) 未读其他提案，独立提出先统一接口、筛选与验收，再有界继续。它与本文在“不扩大预算、不推翻工程、当前直立结果不达标”上收敛，侧重点更偏接口和 critic。

本文不全盘接受盲审的根因判断。来源权重新增三列为零，并不代表其余身体反馈全部断路；后续 A/B 已有非零新输入响应但没有稳定行走收益。因此，不建议重新把放大输入作为主路线。价值损失绝对值也不能单独定义 actor 开放门槛；目标尺度、bootstrap、组内拟合和策略变化都需一起解释。现有 vloss 数字不能证明继续采样必然扩大漂移。
