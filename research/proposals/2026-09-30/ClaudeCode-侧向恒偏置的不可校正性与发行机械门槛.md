## 一、结论摘要

1. **当前模型仍有限制，但主要的那个不是"稳定性不足"，而是"残余偏置在现有架构下不可校正"。** 我重算出的直接证据是：新主候选 9 个 120 秒回合中，`max|y| / |终点 y|` 为 1.000–1.057——**整条轨迹基本是一条单调斜线**，不是随机游走，不是极限环，不是发散。这是"恒定扰动 + 无积分作用"的教科书特征，而不是不稳定。
2. **当前状态科学上够格发行，但机械上今天发不了。** 我逐行核了发行链，`release_evidence.build_report` 会在新证据上直接抛异常，`matches_checkpoint` 会让预览导出器拒绝。这不是"再跑一次评估"能解决的，是协议版本升级 + 适配器的工作。
3. **上肢：同意"可分阶段接入"，但反对"先建身体"。** 建议把顺序倒过来：先补上侧向回路与一个等步数对照（两者都零训练），再动身体。理由见第六节——摆臂最有价值的作用恰恰是侧向稳定，而当前的侧向指标还不是一个被闭环控制的量。

## 三、机制归因：为什么两者都漂，以及为什么训练治不好

我把这条链完整跑通了，每一环都有代码出处。

### 3.1 奖励看不见这个量级

`app/ppo_yumi.py:374-376`：

```python
reward = (1.5 * torch.exp(-4 * (vx - env.command[:, 0]).square())
          + 0.6 * torch.exp(-args.lateral_precision * vy.square())
          + 0.8 * torch.exp(-3 * yaw.square())
```

`vx, vy = env.qvel[:, 0], env.qvel[:, 1]`（`ppo_yumi.py:365`），世界系瞬时速度。`--lateral-precision` 默认 6.0（`ppo_yumi.py:631`）。

代入实测值：教师 3029 的稳态侧速为 7.03 mm/s 时，该奖励项为 `0.6·exp(-6·0.00703²) = 0.599822`，与理想值 0.6 相差 **1.78×10⁻⁴**；教师 3030 相差 **4.31×10⁻⁵**。而单步奖励的其余部分量级为 1.5（前进）+ 0.8（朝向）+ 0.3（直立）+ 0.1，跌倒惩罚 −1.0，动作幅度惩罚 −0.002·a²。

也就是说：**这个横向项在实测 vy 处与满分相差约 6×10⁻⁵ 相对量**，比同一个奖励里 PPO 确实在优化的惩罚项小 3–4 个数量级。高斯项的有效尺度是 1/√precision：precision 6 时 0.408 m/s，precision 60 时 0.129 m/s——分别是实测残余的 58 倍和 18 倍。所以 `DIRECTION_CONTROL_20260929.md` 里 6→60 的对照（长走 0.6745 → 0.2032 m）之所以"改善了直线但打崩了抗扰（正向推扰 6/9、跌倒 3 次）"，正是因为它是在用一个仍然够不着的尺度去挤压一个已经被噪声主导的梯度。

**推论：继续加训练预算或加容量，不可能消掉这个残余。**教师两种子、52M 步的成绩已经把这个上界测出来了。

### 3.2 观测里根本没有 y

`app/sim.py:143-156` 的观测拼装顺序是：角速度(3) + 重力(3) + 命令(3) + **关节**位置偏差(12) + 关节速度(12) + 上一动作(12) + sin/cos 相位(2)，`observation_size == 50` 时追加 `qvel[:2]·0.25` 与 `qpos[2]−height_reference`。

`qpos[7:]` 是各关节角，不是浮动基座位置。**观测里没有世界坐标 x、y**，只有速度。对策略而言，`vy = 0.004 m/s` 与 `vy = 0` 是近乎同一帧输入，而"已经漂了 0.8 m"这一事实**完全不可观测**。

### 3.3 网络没有跨控制步的记忆

`app/full_brain.py:72-85`：

```python
def forward(self, observation, state=None, lesion=False):
    ...
    activity = torch.zeros_like(signal) if state is None else state
    for _ in range(self.neural_steps):
        activity = 0.2 * activity + 0.8 * torch.tanh(...)
```

三处调用都只传一个位置参数，`state` 恒为 `None`：训练 `ppo_yumi.py:356` (`policy(obs)`)、原生评估 `evaluate_direction.py:47`、`Body.step` (`sim.py:163`)。所以每个控制步的神经元活动都从**全零**出发，只做 4 次定点迭代。跨步之间唯一保留的信息是 `self.action`（上一动作，`sim.py:150`）。

**因此：网络既看不到位置 y，也不能对 vy 积分。**一个常值侧向速度偏差对这套系统是**结构性不可见的**。

### 3.4 外层回路是纯比例、且只作用于 yaw

`app/evaluate_direction.py:46`：

```python
obs = np.stack([b.motor_observation([v, args.vy_command,
      float(np.clip(-b.observation()[1]*args.yaw_feedback_gain, -.2, .2))]) ...])
```

`Body.observation()` 在 `sim.py:137-141` 返回 `(gravity, yaw)`，所以 `observation()[1]` 是 **yaw**，不是 y。同一条式子还硬编码在 `evaluate_locomotion.py:98`、`imitate_yumi.py:60`，并且**在教师训练循环里也在跑**（`ppo_yumi.py:354`）：

```python
env.command[:, 2] = (-quad_yaw(env.qpos) * 1.4).clamp(-0.2, 0.2)
```

控制论上这是一个 type-0 回路（只有比例、无积分）作用在一个常值扰动上——**必然留下常值稳态误差**。而分解数据证明这个 yaw 回路本身工作正常：主候选 0.65 档 `heading_y_m = +0.3805`（由朝向贡献的侧移只有 0.38 m），`body_lateral_y_m = −1.2101`（身体系侧滑贡献 −1.21 m）。**残余几乎全部落在没有任何控制器观测的身体系侧滑上。**

### 3.5 唯一可能的快速修复，目前是断的

命令向量里**有** vy 通道（`cmd_scale = [2.0, 2.0, 0.25]`，`sim.py:148`），且 `--vy-command` 是评估器的现成参数（`evaluate_direction.py:133`）。但 `DIRECTION_CONTROL_20260929.md:35` 记录的 ±0.05 m/s 横向命令探针在主候选上造成 5/9 与 9/9 跌倒——**当前策略不能直接接受未验证的横向命令**。

注意那次探针用的是旧的 ridge 学生（`f1a20071` 一系），不是新的 S1 候选。新候选的第 48 列（世界系 vy）是**真的被训练过**的（`train_sensory_readout.py:26-27`，梯度与输入响应已在 `pair_execution.json` 中记录：`initial_input_response` 从 C0 的 0.0 变为 S1 的非零）。命令通道（观测 6/7/8 列）依然冻结，所以这仍是分布外输入——但**"新候选能不能对 vy 命令产生合理响应"这件事，目前没有任何人测过**，而它是决定"漂移能否用控制器而非重训解决"的唯一分水岭。

## 六、上肢判断：同意接入，反对"先建身体"

### 6.1 事实基线（逐项核实）

- **不存在任何手臂刚体。** `yumi.xml` 共 13 个 body、13 个 joint（1 free + 12 hinge）、12 个 actuator。上臂/前臂/手全部折进 pelvis 的 25.7 kg 惯量（`yumi.xml:27`，注释在 15–17 行："手臂与躯干固定（与 G1 代理一致），不参与关节控制"）。
- **总质量 38.04 kg，其中 67.6% 是一个手写惯量的刚体。** 好消息是注释说明了质量本已按 Dempster 节段比例分配，所以拆分有现成依据而不是从零假设（Dempster 上肢各段约占总质量 2.8%/1.6%/0.6% 每侧，38 kg 下合计约 3.8 kg，躯干+头降至约 21.9 kg——**这是提案推算，不是本仓库实测，实施时需与既有注释口径对齐并另行登记**）。
- **接口没有布局契约。** `INTERFACE_KEYS`（`sim.py:30-33`）只带 `observation_size`，**不带关节名、不带动作维度**；`export_preview_weights.py` 全文没有 `action_size == 关节数` 的断言（我逐行看过 119–200 行）。今天唯一的显式守卫是 `sim.py:61-62` 的 `size not in (47, 50)` 和若干形状崩溃。
- **显示层的手臂是程序化假动作。** `web/main.js:270-271`：上臂角度 = `-q[i]*0.48`，其中 `q[i]` 是**同侧大腿**的 pitch；肘部恒为 ±0.13。`web/preview.js:289-296` 是同一段代码的副本。渲染的关节数是字面量（`main.js:169,676`、`preview.js:38,339`）。
- **浏览器物理硬编码 12 约十处**：`web/body-wasm.js:54-56,69,105-107,119-127`；只有 `observation_size` 是动态的。

### 6.2 三个具体的、会在实施中咬人的风险

**风险 1：动作索引按位置硬编码，插入关节会静默错位。** 这不是假设，是已经存在的代码形态：

- `evaluate_direction.py:36-38`：`offset[[1, 7]] = hip_roll`、`offset[[5, 11]] = ankle_roll`——**按序号**寻址髋 roll 与踝 roll。
- `ppo_yumi.py:328`：`knee_idx = torch.tensor([10, 16])  # qpos[7+3], qpos[7+9]`——奖励函数里的膝关节索引。
- `evaluate_locomotion.py:122`、`evaluate_direction.py:64`：同一对索引。

如果新关节按"左臂接在左腿之后"之类的自然顺序插入，这些索引会**全部指错关节而不会报错**，而且奖励函数会开始惩罚错误的关节。`research/experiments/HOME_REFERENCE_MISMATCH_20260916.md` 记录过一次同类的静默错配（`checkpoint.load()` 当时只校验 graph hash 与 feature version，不校验 home，直到页面 404 才暴露）。**加 DOF 之前先加布局契约（关节名列表 + 布局版本号 + 显式 `action_size == len(joint_names)` 断言），是全仓库当前风险最高的改动前必须先做的一件事。**

**风险 2：任何身体改动会自动作废全部现有证据，且"重验基线"是一次完整重验收。** `evaluate_direction.py:96` 把 `body_xml_sha256`（`app/yumi_description/*.xml` 的全部哈希）写进每份评估；`body_config.json` 与 `meta.physics_interface` 在 `preview.js:90-135` 按 1e-6 容差互校。所以改了 XML，`1e1c3160` 与 `fe386851` 的 72 回合全部失效，**必须重跑 72×2 回合**。这不是 smoke test，要按完整验收排预算。而且通过的裕度并不宽松：主候选最大 \|y\| 0.837 m 对 2.0 m 走廊看似有余，但第一段矩阵里 C0 有 3/4 格点卡在走廊边界（`analysis.json` stage1）。

**风险 3：拆分质量会改变步态本身，而当前步态是 RL 在旧质量分布上解出来的。** 25.7 kg → 约 21.9 kg 的躯干、加上约 3.8 kg 悬在两侧的摆臂，改变的是质心高度与惯量张量，而这正是步态解的一部分。教师两个种子、学生八个格点，全部是在旧分布上得到的。所以"上肢辅助平衡"的第一步实验，测的其实是"这个步态有多依赖那团配重"——这本身就是有价值的信息，但要知道自己在测什么。

### 6.3 排序分歧：我认为应该倒过来做

被转贴的方案把顺序定为：建身体 → 固定手臂复验基线 → 训练小幅动作 → 比较三种摆臂 → 扩展。**我同意第 1、2 步的内容，但不同意它们排在前面。**

理由是：摆臂最有价值的物理作用是**角动量侧向稳定**，也就是说，手臂的天然任务指标就是 §2 测出来的那个残余横向偏置。如果先建身体、先把手臂固定住复验走路、再训练摆臂，那么训练摆臂时的验收指标会是"走廊 2 m 仍然通过"——一个**下肢本来就已通过**的判据。这样得到的"学习摆臂有效"结论无法与"质量分布变了"区分，正好落进方案自己第 3 步想避免的那个陷阱。

反过来，如果先做 §7 的 D1/D2，就能在动手之前知道：**这个残余是可以用一个慢速外环消掉的（D2 成功），还是必须由身体产生侧向冲量（D2 失败 → 手臂成为唯一自然执行器）**。这两个分支对应完全不同的上肢设计：前者根本不需要手臂来解决侧向问题；后者则应该把手臂放在侧向回路里训练，而不是先固定再解除固定。

具体到"上肢接入是否需要先解决漂移"——**不需要等地漂归零，但需要先知道漂移属于上面哪一类**，因为那决定了手臂是被当作装饰、当作抗扰器件、还是当作侧向执行器。这个判断只需要两次零训练实验就能得到。

### 6.4 如果用户决定现在就动手，我建议的最小第一步

我同意被转贴方案的第 1 步，但把它重新定义为**一次完整重验收 + 一个测量**，而不是一次复验：

1. 先补布局契约（关节名列表 + 版本号 + 导出器断言），再改 XML。
2. 按 Dempster 口径拆分 25.7 kg，登记每个新刚体的质量/质心/惯量与来源（"假设"要标为假设）。
3. **新增 DOF 但不训练它们**：肩 2 + 肘 1 每侧（共 6 DOF），PD 固定在某个姿态，动作维度从 12 扩到 18，新增 6 维输出**从零初始化**以保证初始行为与原候选**逐位一致**（`train_sensory_readout.py:120-122` 已有这个断言范式，直接复用）。
4. 在新身体上重跑主候选的完整 72 回合留出（新种子组），并报告：起点是否逐位一致、通过率变化、以及**残余偏置速率变化了多少**。

这一步的产出是一个数字：**同一条策略、同一个读出，只因为质量分布改变，1% 的侧向偏置变成了多少。**这个数字同时也是后续所有上肢工作的基准线。它不需要任何新训练，是可证伪的，而且直接回答"手臂该不该进入侧向回路"。

## 八、分歧点（与本轮索引摘要及被转贴摘要的显式对照）

我没有读其他提案正文，以下对照基于 `research/proposals/README.md` 的索引摘要与用户转贴的 ZCode 摘要。

**一致处**：v0.2.0 已发行、AGENTS.md 过时（我独立核实）；C0 过门槛使感觉通路非必要；上肢可分阶段接入；等步数对照是缺失的；学习摆臂应排在发行与对照之后。

**分歧处**：

1. **对残余性质的刻画。** 索引摘要里 ZCode 描述为"速度相关的恒定负向 trim"、Qoder 描述为"侧滑角随速度发散"。我的重算给出的是：**主候选在 0.35 与 0.65 档 `max|y|/|终点| = 1.000`，是单调斜坡；且低速档符号为正、高速档为负**——符号随数据与速度改变（A 数据低速 +0.56，B 数据低速 ≈0），所以它不是"恒定负向"，而是"每个控制条件下一个不同的常值偏置"。这个差别重要：如果是恒定的，它可被标定掉；如果随工况变化，标定无效，只能闭环。
2. **对修复手段的排序。** 索引摘要中的路线集中在"读出再拟合/加权/非线性头/教师奖励精化"。我的 §3.1 给出的是这类的**上界论证**：奖励在实测 vy 处的分辨力是 6×10⁻⁵ 相对量，比它同期优化的惩罚项小 3–4 个数量级；教师 52M 步两种子都漂。所以我认为**再拟合类方案（无论加权还是非线性头）预期都不会比已经失败的 ridge1e5、加权 ridge、读出 PPO、教师 precision 60 更好**，因为它们在同一个不可见的信号上做文章。我建议把 D2（外环）排在所有再拟合之前，理由是它不依赖那个信号是否可见。
3. **上肢的排序。** 被转贴方案是"身体→固定手臂复验→训练摆臂"。我主张"先 D2 定性残余 → 再身体"，理由见 §6.3：否则训练摆臂的验收判据是下肢已经通过的判据，无法归因。

如果用户选择先做再拟合类路线，我不反对——但建议**先把 D2 跑了**，它是 18 个回合、零训练，而且它的结果会决定再拟合的目标函数该怎么写。
