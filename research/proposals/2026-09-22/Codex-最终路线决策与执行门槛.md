# 最终路线决策与执行门槛

日期：2026-09-22。本文是综合决策，已参考同日 Codex-independent 的奖励审计、可复现评估提案，以及本轮全部实测结果。不是独立盲审提案。

用户已授权持续推进到最终决策或突破。本轮达到的是**路线决策**，不是行走突破。正常行走、长走、扰动和断连验收仍未完成。

## 决策

**保留完整连接组、Yumi 物理身体和直接关节控制；下一轮改进速度与朝向恢复的训练课程，并更换权重晋升规则。停止原样长训和单纯调大新增输入。暂不重建框架，也不更换目标。**

这最接近用户此前第二类选项的工程行动：调整训练方法。但“路线已经被证明正确”这个前提尚不成立。现有数据既没有证明此架构必然成功，也没有证明它无法成功。决策依据是已有可用的平衡和命令响应，以及当前最明确、最便宜可检验的缺口。

本轮不晋升 A、B 或扩大转向限幅的版本。来源权重及生产预览保持原样。扩大限幅只作为诊断结果保留。

### 观点对比与收敛

- 独立审计最初提出换脚奖励消融及低优先级的跨步神经状态对照；主 Agent 先要求分离评估数值波动，再识别命令响应。后续原生数据将共同优先级缩小到朝向恢复。
- 独立 Agent 曾建议训练命令范围覆盖计划使用的较大限幅；主 Agent 主张第一轮保持 `cap=0.2`，只改变初态覆盖。交叉复核后双方同意后者，以保持单变量比较；只有第一阶段有效，才扩展命令范围。
- 奖励调整仍有不同候选：独立 Agent 倾向移除换脚奖励；主 Agent 要求先测各项贡献，再定跟踪奖励对照。因此本轮没有把任何奖励修改写成已批准实施的事实。
- 最终共同判断是保留连接组和 Yumi。该共识不代替实验，也不证明未来一定成功。

### 评估必须先可信

旧 CUDA 稀疏推理的约 `1e-7` 动作差，以及 Warp 接触轨迹的数值变化，会影响长回合排序。开启 PyTorch deterministic algorithms 没有消除此问题。

新增实验使用固定累加顺序的 CSR 推理和原生 MuJoCo。三组初态中，来源正常、重复、零新输入均得到完全相同的 qpos/qvel 轨迹哈希；转向限幅试验的来源条件也精确复现。后续开发比较采用这条已校准路径。GPU 训练内评估仍可做快速筛查，其分数不能跨后端直接排序或代替原生验收。

精确重复只控制了数值波动。它不代表对不同初态、训练种子和真实物理具有鲁棒性。此实验后端尚未接入生产服务；上线前需要完成集成和接口回归。

### 命令响应不等于通用转向训练

当前 PPO 的第三个 command 是 `clip(-1.4*yaw, -0.2, 0.2)`，奖励偏好世界朝向零；它不是经过独立 yaw-rate 跟踪训练的通用转向控制器。因此，固定正命令没有实现指定正转速，不能单独判为违反训练契约。

配对扫查的意义是识别纠偏输入的方向和强度。低速时正向输入常不足以抵消偏航，原闭环先导测试平均约 83.2% 时间处于限幅。扩大上限改善速度通过数，却没有改善方向通过数。这支持对速度、朝向及初态覆盖做联合诊断和训练，不能只把旋钮继续调大。

## 下一轮执行方案

这是后续训练的具体方案，**尚未执行，收益尚待检验**。本轮目标在交付此决策后结束，不把计划算成实验结果。

### 1. 固定比较方法

- 保留来源、A、B checkpoint 和配套 PPO 状态，按 SHA-256 绑定结果。
- 将已校准的原生评估整理成可复用入口；固定 batch 和物理接口，启动时跑正常重复与零通道阴性对照。
- 报告每档速度的成功、速度误差、方向、跌倒；score 只作辅助指标。
- 开发初态用于迭代。最终另留未使用的初态，执行 30 秒、120 秒、轻推和断连验收。

### 2. 首个训练对照只改初态覆盖

训练问题改为：**模型能否在不同速度下，从正负朝向偏差恢复到直线行走？**

- 控制组继续现有 reset 分布；实验组在相同分布上增加平衡的初始偏航 `0 / ±0.1 / ±0.2 rad`。不同时改奖励、命令限幅、动作缩放或网络结构。
- 继续使用 50 维完整图、相同来源权重和已隔离的 critic 输入统计。两个分支保持相同 actor 标准化和优化器恢复规则。
- 使用两个独立训练种子，成对比较。先各做 1 轮 value warmup 加 20 轮 actor 更新；128 worlds、128 steps、4 epochs、batch 512、actor LR `5e-6`，沿用上一轮已验证配方。开始前保存完整命令和源状态哈希。
- 每个进程设置 20 分钟硬上限；到限仅保存实验状态并结束该训练进程。不得因此关闭实例。若设备速度不足以完成等量更新，只比較共同完成的轮数。
- 用相同原生开发初态比较零偏航正常行走，并另报正负偏航恢复测试。新增训练初态只能作为开发测试，不能充当独立泛化结果。

这个对照只验证“初态覆盖是否有帮助”。若无收益，不能据此否定所有课程学习。

### 3. 进入下一阶段的门槛

以下是预先设定的工程门槛，不是由本轮数据推导的统计显著性阈值：

- 两个训练种子分别比较：实验组在 27 个正常初态上，成功数至少比对应控制组多 6，方向通过数至少多 5。
- 每个种子的跌倒数不得增加超过 1；三档速度平均绝对误差均不得恶化超过 `0.02 m/s`。
- 每个种子的平均绝对横移不得增加；不能用更高成功数抵消其余回合更严重的横漂。
- 正负朝向恢复均有改善，不能只修复一侧；同时记录恢复时间及失败回合，避免平均值掩盖偏置。
- 只有两次独立训练均过门槛，才扩大训练时间和扰动范围。仍不得跳过最终留出验收。

若未过门槛，停止延长该实验组；下一变量才是任务奖励。先记录各奖励项的轨迹贡献，再做朝向/速度跟踪奖励的单变量对照。暂不同时改神经展开步数、跨步记忆和读出冻结，避免再次无法归因。

### 4. 何时转向新方法

若初态覆盖和奖励对照均无法在两个训练种子中取得稳定收益，升级到 **Yumi 本体策略教师与连接组蒸馏的可行性对照**：先验证同一身体和任务能否由较小策略学会，再比较连接组学生。教师用于训练与诊断，最终运行仍须由连接组直接输出关节动作。

这是后续分支，不是本轮已验证结论。只有同任务的教师/学生比较，才有更直接的依据区分身体/任务难度与连接组优化或容量限制。仅凭现有失败，不更换身体、不放弃完整连接组目标。

## 资源与交付边界

继续使用当前 4090D 24 GB。训练效率优化应以每秒有效样本和更新耗时为准；不因显存空闲就盲目增加 worlds。前序更新阶段已采样到 96% GPU 利用率，不能把显存余量当作算力余量。

本轮实测与脚本已在云端和本地保留，来源 checkpoint 未改动。实例按用户要求持续开机，有卡空闲继续计费。没有执行关机、释放 GPU 或切换无卡模式。
