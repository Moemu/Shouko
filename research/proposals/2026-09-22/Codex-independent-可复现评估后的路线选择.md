# 可复现评估后的路线选择

**审查者：** Codex independent
**日期：** 2026-09-22

本提案未读取其他新提案的结论。只读了 `runs/yumi_route_decision_20260922/ordered_csr.json`、`native_feedback.json`、`native_feedback27.json`、`command_response.json`、`command_factorial.json`、`heading_limits.json`、`native_summary.json`、`repeatability.json` 及相关生产代码；没有运行 GPU、云端实验或修改代码。

## 结论先行

下一步优先做**分速度 heading recovery 训练**，暂缓原样长训和泛化的奖励对照。命令 factorial 与 heading cap 对照已确认 command 和外层限幅都有作用，但还没有形成稳定的方向控制。理由是：

- 固定顺序 CSR 加原生 MuJoCo 下，首批 `source`、`source_repeat` 和 `source_zero` 的 9 条 30 秒轨迹 hash 完全相同。这个 cohort 中源策略得分 `0.4455`，2/9 成功，0 次跌倒。
- 同一评估中，`control` 为 `0.3864`（2/9），`scaled` 为 `0.3716`（1/9），`scaled_zero` 为 `0.4340`（1/9，1 次跌倒）。这批数据没有显示 PPO 微调稳定超过源策略。
- 新增 27 初态结果后，source、control、scaled 的三 cohort 平均得分分别为 `0.3392`、`0.3135`、`0.3680`；scaled 在第二 cohort 的 `0.4658` 没有在其他 cohort 重现，不能称为突破。源策略在首批 9 个初态全部存活，但 27 初态合计有 2 次跌倒，因此需要区分初态波动与策略效应。
- `command_factorial.json` 显示，在 turn=0 时目标速度从 0.35 到 0.65，9/9 初态的端点身体前速上升；固定转向从 `-0.2` 到 `+0.2` 时，27 次配对中的 25 次 yaw rate 上升。但低速正命令只有 1/9 条轨迹实际为正 yaw，中速为 2/9，高速为 6/9，说明 command 被使用，却没有稳定实现方向正确的转向。
- `heading_limits.json` 在同一 27 初态上把 heading cap 从 `0.2` 提到 `0.4/0.8` 后，得分为 `0.3392/0.4816/0.5150`，速度条件通过数为 `3/11/16`，但方向条件通过数为 `11/6/9`，横移为 `3.938/4.371/4.319 m`，跌倒数为 `2/0/1`。这证明外层限幅影响速度与朝向的权衡，却没有全面修复方向控制。
- 因此下一步应进入分速度的 heading recovery 训练，并平衡正负朝向初态；不要按单一 score 直接晋升 cap=0.8，也不要原样继续长训。

这不是拒绝 PPO。它把已完成的控制边界诊断转化为下一轮训练课程，而不是直接晋升一个未训练的 cap。

### 生产路径

`app/evaluate_full.py:36-43` 每步先读取身体 yaw，再构造 `[speed, 0, yaw_rate]`，调用策略得到 12 个关节动作，最后交给 `Body.step_joints()`。

`app/evaluate_full.py:37` 的 `yaw_rate` 是 `-yaw * 1.4` 的闭环修正。原 30 秒评估没有真正扫描正负转向命令，所以不能只用原评估判断策略的转向响应。

`app/sim.py:143-156` 将角速度、重力、三维 command、关节状态、上一动作、相位，以及 50 维接口中的水平速度和髋部高度组成观测。`app/full_brain.py:72-85` 把观测编码到连接组，再经输出神经元和 readout 产生 12 个动作。`app/sim.py:166-175` 将动作转换为 home pose 加动作缩放，并用 PD 执行。

训练路径在 `app/ppo_yumi.py:288-325` 使用速度命令和相同的 yaw 闭环修正；factorial 是对这个 command 的开发诊断，不是“±0.2 rad/s 转向跟踪”的训练契约。

### 先导 command probe

`command_response.json` 对源检查点做了 9 初态、12 秒的先导测试。固定转向命令的平均 yaw rate 为：`turn_negative=-0.0914`、`turn_zero=-0.0616`、`turn_positive=-0.0329`。正命令使 yaw rate 相对增大，但三个均值按当前符号仍为负；正命令组有 1 次跌倒，另外两组没有跌倒。

这说明第三个 command 可能影响动作，但还不能说它已实现方向正确的转向。该先导测试仍把速度和初态混在同一批 9 条轨迹中，且固定转向试验不追踪世界 heading=0。factorial 只消除速度与初态的混杂，不把固定转向试验变成“追踪 heading=0”的任务。

### Factorial 结果

`command_factorial.json` 已完成 9 初态 × 3 速度 × 3 固定转向、每条 12 秒的配对测试。turn=0 时，0.35 到 0.65 的身体前速端点上升为 9/9；严格要求三个速度层级逐级上升时为 7/9。yaw command 从 `-0.2` 到 `+0.2` 的 yaw rate 上升为 25/27，但 `+0.2` 的正 yaw 比例按速度分别只有 1/9、2/9、6/9。

factorial 记录的 command 统计为 mean `[0.9, 0, 0]`、std `[0.3688, 0.05, 0.05]`、`cmd_scale=[2, 2, 0.25]`。生产代码仍在 `app/full_brain.py:74` 对归一化观测做 `[-10,10]` 截断；按该 std，`+0.2`、`+0.4`、`+0.8` 的第三通道约对应 `+1`、`+2`、`+4`，所以 cap 扫查不会触碰这个全局截断，但 `+0.4/+0.8` 超出当前训练命令范围，属于诊断性的分布外输入。

### Heading cap 对照结果

`heading_limits.json` 在同一 27 个开发初态上保持 source 权重、速度目标、物理和 ordered CSR 不变，只改变 heading feedback 的外层 cap。结果如下：

| cap | 得分 | 成功 | 跌倒 | 速度条件通过 | 方向条件通过 | 平均横移 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 0.2 | 0.3392 | 2/27 | 2 | 3/27 | 11/27 | 3.938 m |
| 0.4 | 0.4816 | 3/27 | 0 | 11/27 | 6/27 | 4.371 m |
| 0.8 | 0.5150 | 5/27 | 1 | 16/27 | 9/27 | 4.319 m |

较大的 cap 提高速度通过数和总分，但方向通过数下降，横移没有下降。这个对照证明外层 heading 限幅会改变速度与朝向的权衡，却不能单独认定它限制了纠偏，也不能证明 `0.8` 是最终控制值。由于 `0.4/0.8` 超出当前训练分布，该结果应作为课程设计证据，而不是推理权重的直接改进。

## 候选一：分速度 heading recovery 训练（优先级 P0）

**要辨识的问题：** 当前连接组和 Yumi 身体能否在不同速度下学会恢复 heading，而不是只对外层 cap 产生更快或更慢的偏航响应？

**依据：** cap 对照在 27 个匹配初态上明显提高速度条件通过数，但方向通过数从 `11/27` 降到 `6/27` 或 `9/27`，横移没有改善。这说明当前问题是“直线任务的纠偏不足”，不能扩展成“尚未训练的通用转向功能已经失败”。

**建议设计：** 保留全图连接组、Yumi 身体、PD、当前速度目标和 `cap=0.2`。第一阶段只按速度层级生成 heading 偏差，并平衡正负初始朝向与恢复方向；不同时扩大 cap。先做两个训练 seed，使用相同的 native 27 初态做 paired 验收。只有第一阶段改善方向与横移后，第二阶段才逐步把训练 command/cap 扩到 `0.4`、再到 `0.8`。

**验收指标：** 分速度的目标速度误差、`mean_abs_yaw`、末端 yaw、`lateral_m`、方向条件、跌倒、足部交替和直立度。总 score 只能作摘要；必须同时要求方向和横移不恶化。

**边界：** `cap=0.4/0.8` 的现有权重结果不是训练成果。它只证明外层限幅会改变速度与朝向的权衡，不能单独证明 cap 限制了纠偏。若第一阶段后仍只有 yaw rate 幅度变化而没有方向恢复，再查 readout、奖励与步态机制；只有在此之后才扩大 command/cap 范围。

## 候选二：单变量 PPO 奖励对照（优先级 P1）

只有候选一完成后仍显示 command 可用、但横移没有改善，才做一个短的、配对的 PPO 对照。保持 source checkpoint、随机种子、worlds、rollout 长度和 optimizer 相同，只移除 `app/ppo_yumi.py:337` 的 `0.4 * switched.float()`，与当前奖励形成两组。该对照只回答“换脚 credit 是否改善有效前进，或增加横漂”，不同时改变速度项和姿态项。

两组都用相同的初态，并用两个训练 seed 覆盖与 27 初态诊断相同规模的 native paired cohort。选择指标是 `lateral_m`、目标速度误差、成功率和跌倒率；rollout reward 与 Value loss 只作训练记录。只有当改动组在匹配初态上同时降低横移或提高成功率，并超过 native matched-cohort 的波动，才进入更长训练。不要把旧 Warp 开放环重放的 qpos 差异当作 native 评估误差条。否则停止该奖励方向，回到输入/命令或步态机制诊断。

## 测量边界

`repeatability.json` 显示相同输入的神经推理 RMS 约 `1.0e-7`。旧的 6 秒固定动作重放使用 Warp 物理；其 qpos 向量最大绝对差约 `1.18–1.51`，但 qpos 混合了角度、四元数和根位置，不能标成米。根位置 RMS 约 `0.612–0.617 m`。

旧 Warp 开放环重放与新增 native MuJoCo 加 ordered CSR 的 exact 评估使用了不同物理后端、累加顺序和动作路径，不能把它们的差异简单归因于闭环反馈，也不能把旧 qpos 差异当作 native 误差条。后续 native 比较应使用匹配初态、匹配训练复现和闭环评估。

当前证据支持“保留连接组与 Yumi，停止原样长训和单 score 晋升，先做分速度、平衡正负朝向的 heading recovery 训练，再做单变量奖励对照”。它不支持把 B 的单 cohort 改善称为突破，也不支持宣布当前结构已经正确或不可能；最终判断必须来自两个训练 seed 的 matched native 验收。

## 最终方向（独立判断）

1. 保留完整连接组、Yumi 身体和现有物理接口。当前证据显示动作、速度 command 和 heading command 都能影响身体，尚不足以判定结构错误。
2. 停止原样 PPO 长训。第一阶段保持 cap=0.2，按速度层级训练 heading recovery，平衡正负初始朝向和恢复方向；用两个训练 seed 和相同 native 初态验收。
3. 将 cap=0.4/0.8 作为第二阶段课程范围的候选，不直接作为现有权重的生产改动。验收同时要求速度、方向、横移、跌倒和足部条件改善。
4. 只有 heading recovery 课程稳定后，才做 `switched` 单变量奖励对照。
