## 热启动验证（两步判别）

1. 首次 47-vs-50 rollout 对比"未通过"（Δ0.34 m/s、1/32 摔倒不匹配）——但判据选错了：
   直立世系是边际稳定系统，同条件重复评估的固有散布就有 ±0.1-0.22。
2. 判别实验（`runs/yumi_obs50/discriminate.{py,json}`）：
   - **A 前向映射等价（CPU，无混沌参与）：max diff = 0.0**——扩维机制逐位正确；
   - **B 噪声包络**：47 维对自身同进程连评两次，per-world Δmax = 0.223——
     与 47-vs-50 的 0.34 同量级。
   **结论：热启动成立；rollout 级逐位判据对该被控对象不适用。**

## ppo17 训练（云端 4090D，12 × 170 s 脉冲，09:40-10:20，~300 迭代）

配置：ppo15 配方（freeze-brain、lr 1e-4、std 0.08、value-warmup 6、epochs 4、
target-kl 0.02）+ `--knee-gate stance` + 50 维 + `--worlds 32`。

**结果：训练净效果 ≈ 0，且暴露两个工程缺陷。**

1. **脉冲内退化贯穿始终**：每个 burst 基线 score 0.35-0.48，25 迭代内普遍跌至
   0.0-0.35（仅 burst 3 iter 20 冲到 0.442/7 successes，combined 0.815 未过线）。
   这是 ppo9/10 崩解签名在冻边配方下的温和重演。
2. **价值网全程未收敛**：v_loss 80-570（历史健康值 ~10），即使 burst 2-12 通过
   `--resume-state` 恢复价值网与优化器。推断：直立世系处于稳定边缘，探索噪声
   （std 0.08）下摔倒/存活的回报分布重尾，价值网拟合下限被抬高；优势信噪比低
   又反过来驱动策略漂移（clipfrac 0.2-0.3），互为因果。
3. **棘轮统计缺陷（本次最重要的方法论发现）**：`best.pt`（2abe0093，stored
   combined 0.869）与扩维源模型**张量逐位相同**（max diff 0.0，审计
   `audit_best.json`）。棘轮在 12 个 burst 里反复重评同一权重，把同一次幸运抽样
   （0.844→0.869）固化为门槛，从未接受任何训练后的权重。单次评估 + max 选择
   = 赢家诅咒；以评估噪声 σ≈0.09-0.10 计，stored 0.869 对真实 ~0.42 属预期偏移。

## 对并行分析（另一 Agent）的修正

- 其"训练确实提升 +0.09（0.33→0.42）"**不成立**：best.pt 与源张量相同，两个
  三次评估的均值差在 n=3、σ≈0.09 下无显著性；配对评估 0.424 vs 0.433 证实。
- 其选项 C（`posture_select_w` 压制 score 进步）**不成立**：直立世系 mean_height
  恒 0.90，身高奖励 (0.90-0.80)/0.13×0.5 = 0.385 为常数加项，不产生差异化压制。
- 其脉冲内退化与 v_loss 诊断**成立**，且其"每个 burst 重新预热价值网"的机理描述
  不准确——burst 2+ 价值网是跨 burst 恢复的，未收敛是拟合下限问题而非重置问题。
- 该分析后整理为正式提案 `research/NEXT_STEP_PROPOSAL_20260920(Cline).md`（第五方）。
  其 Step 0/1 骨架（修评估协议 → 价值先导连续训练）与本编年"下一步候选 1+2"收敛；
  其"价值网因 47→50 维 shape 不匹配而未加载"的机理**不成立**——本实验 `--runs-dir`
  隔离使 burst 1 起全部状态文件均为新建 50 维（burst 1 未传 `--resume-state`），
  且代码对 value 状态不兼容会显式抛错（`ppo_yumi.py:110-111`）。其"sensor 补丁
  +27% 提升"为头部结论性错误（见上文 best_vs_source 张量审计）。其 Step 0 的
  三次均值修法缺少"同权重重评不得上调 stored 值"规则，单独实施仍会被重评漂移攻破。

## 附带事实

- 训练环境（0.8 s 钟、32 worlds）下直立世系的 cmd→vx 与 native（1.0 s）显著不同：
  0.35/0.5/0.65 档实测 ~0.02/0.24/0.30——时钟对直立推进的影响在两条路径上不可互换
  （与 Step 0 扫频的窄工作带一致）。
- 配对三点斜率（噪声大，仅作参考）：source 0.94 / best 0.72 / last 0.78——
  无显著改善证据；last.pt 编码器漂移 max 0.0015（新列学习极慢，encoder lr 5e-5）。
- 本轮为 16:9 折中：原计划本机 16 worlds（资源门控），用户开机后全部转云端 32 worlds。
- 本机资源事故：09-20 上午内存耗尽（0.7/15.2 GB free）触发 GPU 内核崩溃；
  已留 `runs/yumi_obs50/run_burst_local.py`（RAM/显存门控启动器）备本机复用。

## 下一步候选（待拍板）

1. **修棘轮（必须，先于任何再训）**：候选超过 stored best 须连续 2 次评估确认
   （或 2 次均值 + margin > 噪声 σ）；同权重重评不得上调 stored 值（按张量哈希识别）。
2. **价值先导连续训练**（另一 Agent 选项 B 的修正版）：单轮长跑，value-only 直到
   v_loss < ~30（上限 30 迭代），再开策略梯度；评估每次存 per-cmd 斜率作为主监控量
   （score 噪声太大）。
3. 若 2 后斜率仍无改善：承认"补传感器对颤动形态无梯度可用"，转足端离地塑形
   （Step 0 的形态学结论），或按用户先前意见回退深蹲世系。
4. 评估协议升级：所有模型间比较一律配对 + ≥3 次重复；单次评估只作监控不作结论。

## 第二轮（连续训练）预注册——写于启动前

用户定稿执行合并路线（棘轮修复 + 价值先导连续训练）。代码改动：`same_weights()`
同权重守卫（重评只重锚定、不上调）、`combined_bar` 显式持久化、候选接棒需两次评估
均值超过 bar + margin（默认 0.03）、评估记录 `transfer_slope` 与 per-cmd 分档均速、
`--value-abort-vloss` 预注册中止点。训练配置：单轮 1800 s、value-warmup 30、
lr 5e-5、其余同 ppo17 第一轮（freeze-brain、std 0.08、knee-gate stance、50 维、
tall yaml 配对、32 worlds）。

**判据（先于结果写下）**：

1. **中止**：value-only 30 迭代后 v_loss 5 期滑动均值仍 >50 → 判定"价值拟合下限/
   重尾回报"假设胜出，跳过策略更新直接结束（后续选项：加深 value 网 / 回报归一化）。
2. **训练成功**：0.35 档均速从基线 ~0.02 m/s 显著抬升（>0.10），或传递斜率在多次
   评估中稳定超过基线（基线：source 三点斜率 0.94，0.35/0.5/0.65 档 ~0.02/0.24/0.30）。
3. **训练失败**：v_loss 达标但斜率/per-cmd 无变化 → "补传感器对颤动形态无梯度可用"
   成立，转足端离地塑形或回退深蹲世系（待用户拍板）。
4. 全程骨盆高 <0.85 m 或连续摔倒即人工停止。

## 连续训练第一 aborted：预注册中止点触发（2026-09-21）

配置：单轮 1800 s、value-warmup 30、`--value-abort-vloss 50`、lr 5e-5、
从 ppo17 棘轮修复后的 `best.pt` 热启动。结果：**30 迭代纯价值训练后 v_loss
5 期滑动均值 94.76 > 50，中止点按预注册触发，策略更新被跳过**（`cont50.log`）。

价值 loss 轨迹：158 → 谷底 ~50（iter 12-15）→ **回升**至 80-108；冻结策略下
滚动奖励均值同期从 ~2.9 漂移至 ~1.8。两个推断（未单独验证）：
- 谷底-回升形态 + 冻结策略下奖励漂移，指向 ppo10 已确诊的「固有漂移」——
  滚动状态分布在漂移，价值网追逐移动靶；
- 单靠延长预热未必收敛，但"30 迭代不够"与"存在不可约下限"两个假设仍未分离。

**分支执行（同族假设测试到位）**：价值门改为双侧——v_loss 达标（连续 2 个
5 期窗口 < 50）即提前进入策略更新；`--value-warmup 300` 给足收敛预算
（~45 min）；预算耗尽仍未达标则带完整收敛曲线结束，判定"价值拟合下限"成立。
价值状态从上次中止点续训（`--resume last.pt --resume-state`，其中价值已训 30 迭代；
策略权重仍为源模型，因冻结未被改动）。
