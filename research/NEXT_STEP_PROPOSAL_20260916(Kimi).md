## 0. 一页结论

姿势目标（骨盆高 0.90 m、膝直、不摔）已达成，唯一缺口是速度跟踪：直立世系全档位卡 ~0.2 m/s vs 目标 0.35~0.65。

我的判断：**瓶颈既不在奖励权重，也（暂时）不在步频接口，而在信息回路——奖励要求策略闭环调节的两个量（前进线速度、骨盆高度），都不在 47 维观测里，且策略跨控制步无记忆，连积分估计的路也被堵死。** 这一个结构缺陷能统一解释三组互不相关的实测现象（见 §2），而奖励权重和时钟改动都不能。

推荐顺序（全部从 `best_tall.pt` 热启动）：

1. **Step 0（5 分钟，零训练）**：用冻结 best 测 (cmd, vx) 传递曲线，量化前馈速度通道死到什么程度，作为改动前后对照基线。
2. **Step 1（唯一关键改动，~20 行）**：观测补 `qvel[0:2]` 与相对骨盆高，encoder 新列零初始化热启动，观测分布零扰动。
3. **Step 2（一行）**：膝惩罚改支撑腿门控——现行写法在直接补贴小碎步。
4. **Step 3（条件触发，先不动）**：反馈闭合后若速度仍撞墙，再做速度条件化时钟；奖励权重、解冻突触边、从头训练均不建议。

## 2. 核心诊断：被要求闭环的量，策略一个都看不见

### 2.1 观测与奖励的错位（代码层事实）

`ppo_yumi.py:184` 的奖励主项用 `env.qvel[:, 0]`（机身前进线速度）和 `env.qpos[:, 2]`（骨盆高度，经 `height_ramp`，`ppo_yumi.py:208,214`）打分。但 `gpu_body.py:107-112` 的观测向量是：

```python
qvel[3:6]*0.25  +  gravity  +  command*[2,2,0.25]
+ (qpos[7:] - home)  +  qvel[6:]*0.05  +  prev_actions  +  sin/cos(2πt/0.8)
```

共 47 维。**没有 `qvel[0:3]`（线速度），没有 `qpos[2]`（骨盆高度）。** 指令（目标）在观测里，但实际值不在——策略知道"该走多快"，不知道"自己正走多快"。

该布局是 unitree_rl_gym G1 契约的逐字段照搬。对 G1 这是合理设计：教师策略本质是开环定步频播放器，不需要速度反馈。对端到端训练的闭环策略，这是结构性感官缺失。

### 2.2 无记忆堵死了积分估计这条路

`full_brain.py:56-61`：每次控制查询 `state=None` → 活动从零起跑，只做 4 步更新（`neural_steps=4`）。跨控制步无神经记忆。因此策略也无法用"关节速度历史 × 步态相位"间接积分出机身速度——它能看到的只有瞬时快照。

### 2.3 这一个缺陷统一解释三组现象

**现象 A：两个世系都是"单速步态"。**
- 深蹲世系：三档目标的实际速度呈近乎恒定的 +0.15~0.2 超速偏移（0.514/0.616/0.709 对 0.35/0.5/0.65，§1 数据）。
- 直立世系：全档位坍缩到 ~0.2 m/s。
- 解释：速度不可观测 → 闭环不可行 → 策略只能学"cmd→步态"的前馈查表。这张表要穿过冻结的 25.6M 边循环核、仅 ~210k 可训练接口参数（读出 + 编码器 + 偏置，`ppo_yumi.py:74-82`）来表达，两个世系都没学出来，各自退回到自己的"自然速度"。

**现象 B：v_loss≈10（回报预测近乎失效）。**
价值网络与策略共用同一套盲观测。回报方差的最大来源——实际速度、是否接近摔倒高度——对价值函数不可见 → advantage 以噪声为主 → 策略梯度信噪比极低。**推断**：这比"25.6M 边小批量更新"更深层地解释了"从收敛点微调 10~15 轮必崩"（ppo9 第 10 轮达峰后不再超越、ppo10 对照组复现崩解）：即使冻结突触边，盲价值函数也在持续向策略注入噪声梯度。

**现象 C：棘轮盆地锁定。**
ppo15c 十二轮脉冲 score 震荡 0.31~0.47、无一超过第 1 轮的 0.525。策略看不到自己慢 → "加速"的有利扰动与"变晃"的有害扰动在盲价值函数里无法区分 → 只剩探索噪声抽奖，棘轮把第一次运气固化成天花板。

### 2.4 为什么调奖励权重修不了它

把追踪核从 `exp(-4e²)` 锐化到 `exp(-10e²)`、或把 vx 权重 1.5→2.5，都只是**把"走错速度"的惩罚调大——但没有给策略任何知道自己走错了的手段**。惩罚更陡 + 感官不变 = 盆地更窄更深，预期把策略进一步推向小步自保。这与 ppo15c"姿势项加重后速度反而从深蹲世系的 0.55+ 掉到 0.2"的实测方向一致（推断：姿势门控 `walk_gate = vx/cmd`，`ppo_yumi.py:209`，在低速世界饱和，姿势拉力集中在已会走的慢速世界，构成减速的隐含奖励）。

## 3. 第二个独立缺陷：膝惩罚在直接补贴小碎步

`ppo_yumi.py:217`：`-knee_w * relu(knee - 0.5).mean(dim=1)` 对两条腿一视同仁。

但直立化 home（`yumi.yaml` 膝 0.08 rad）下，**任何一次跨步，摆动腿都必须弯膝 ~0.5+ rad 才能抬脚离地**。现行写法因此同时惩罚：
- 支撑腿的深蹲（想罚的）；
- 摆动腿的必要离地弯曲（不想罚的）。

净效果：奖励结构对"迈步"本身课税，客观补贴原地小碎步。这是可以自己改掉的明确设计缺陷，与观测问题独立：**膝惩罚只对支撑腿生效**——以 `feet_z.argmin`（`ppo_yumi.py:188` 已有现成变量）的同侧膝为摆动腿、 exempt 之。

附带机械事实：腿拉直后，"屈膝抬脚"这个最省力的离地机构被删除，推进必须改由髋伸 + 踝蹬做功，而奖励里没有任何一项奖励推进做功。这构成"站直 → 无可用推进方案 → 缩步幅 → 0.2 m/s 地板"的因果链。踝/髋推进项可作为 Step 2 的可选增强，但优先级低于门控修正（门控是删错误激励，推进项是加新激励，前者风险更低）。

## 4. 固定步频是约束，但不是当前瓶颈

`gpu_body.py:108`：`phase = time·2π/0.8`——步频 2.5 步/秒硬编码，不可控。这把"提速"逼成"拉步幅"。

但有两点说明它现在不该先动：

1. **物理容量已证伪"步频不够"**：深蹲世系用同一 0.8 s 时钟、同一 12 关节接口跑出 0.73 m/s 零摔倒（§1 数据出处）。直立腿长更长，同样髋摆幅下步幅更大——0.65 m/s 所需摆幅比深蹲世系已实现的更小（单摆近似，量级判断）。
2. **ppo16 已划定改动边界**：全局时钟 0.8→1.0 s = 观测分布整体重置，combined 从 0.871 掉到 0.802。任何时钟改动必须在工作点连续，而"先证明反馈闭合后仍然撞墙"才是承担该代价的正当理由。

结论：时钟改造排 Step 3，且必须先由 Step 1 后的实测撞墙来触发。

## 5. 推荐方案：三走一测

### Step 0 — 测量（5 分钟，零训练，先跑）

用冻结的 `best_tall.pt` 在 32 个世界（cmd 从 0.15 到 0.75 linspace）跑 30 s，逐世界记录 (cmd, mean_vx, 身高, 膝角)，画 cmd→vx 传递曲线。

- **预期**：曲线接近水平线 vx≈0.2（前馈速度通道死亡），与 §2.3 现象 A 的推断互证。
- **价值**：这是改动前对照基线；若曲线意外地有明显斜率，则"感官缺失"诊断被削弱，讨论应转向价值函数容量分支（§7-Q3）。

### Step 1 — 补观测，零初始化热启动（唯一关键改动，~20 行）

在 `gpu_body.py:107-112` 的观测向量追加 3 维：

```python
self.qvel[:, 0:2] * 0.25,                          # 机身线速度（前/侧）
(self.qpos[:, 2] - self.initial_qpos[2])[:, None]  # 相对骨盆高
```

兼容方案（零扰动热启动）：
- `ConnectomePolicy.encoder`（`full_brain.py:47`）输入维 47→50，**新增 3 列权重零初始化** → 旧 checkpoint 逐位等价，首轮推理输出与改前完全相同；
- `obs_mean`/`obs_std` 缓冲对应扩展（新维 mean=0、std=1 或按 Step 0 实测标定）；
- 47→50 破坏 checkpoint 形状校验，需要一次性转换脚本（加载旧 state_dict → 拼零列 → 另存新 checkpoint，保留原文件）。
- 价值网络输入同步扩维，旧价值权重可弃（价值网络本来就噪声大，重训成本低；`value_warmup` 机制已覆盖冷启动，见 `ppo_yumi.py:243-246`）。

成本：云端 2×170 s burst 即可见分晓。回退：新列零初始化保证改前行为可逐位复现，文件级备份即可。

### Step 2 — 膝惩罚支撑腿门控（一行）

`ppo_yumi.py:217` 的 `relu(knee - 0.5)` 改为只计支撑腿侧（与 Step 1 合并为同一次实验，避免两轮 GPU 开销；两项改动在日志里分别记录 mean_knee/mean_height，归因可行——若担心混杂，也可拆成两个 burst，各 170 s）。

### Step 3 — 条件触发项（现在不做）

- **速度条件化时钟** `f(cmd)`：仅当 Step 1+2 后 0.5 档成功率仍为 0 且 vx 明显撞天花板时启动；标定约束 cmd≈0.2 处 f=1.25 Hz（工作点不变），随 cmd 光滑上浮。
- **踝/髋推进奖励**：仅当门控修正后步幅仍受抑制时加入。
- **扩样本（32→256 worlds）后有条件解冻突触边**：4090D 峰值显存现仅 ~4.4 GiB，余量充足，但这是算法级重构，排在速度锁定之后。

### 明确不做

- **不从零训练**：Yumi 无可用教师（`ppo_yumi.py` 文档字符串：G1 teacher ~1.7 s 摔倒）；现 best 是 G1→Yumi 世代资产。
- **现在不解冻 25.6M 突触边**：样本预算不变的前提下，崩解风险不因补观测而消失。
- **不动奖励权重主结构**：vx 1.5→2.5 或核锐化在感官缺失修复前只会加深盆地（§2.4）。Step 1 见效后再谈微调。
