## 1. LIF 与 WASM 核心

**源码核查入口**：`flybrain/src/brain.c`、`flybrain/flybrain.js`、`flybrain/README.md`、`flybrain/test/`。

脑来自 Shiu 模型与 FlyWire v783。它使用膜电位、突触状态、阈值、重置、不应期和延迟传播。它与我们每次查询内的 `tanh` 活动率迭代不同，不能直接替换矩阵算子后沿用已有权重。

值得读的实现：

- `may_cross`：用膜电位未来上界判断神经元在新输入到达前是否可能发放。
- `advance`：对休眠神经元补算时间衰减，避免每步遍历所有细胞。
- `fb_run`：活动集合、延迟环形缓冲、Poisson 输入和可塑更新的时序。
- `fb_plastic_*`：只为指定突触分配增益和分区，不默认训练全图。
- JS 包装：WASM 内存上的 TypedArray、64 位神经元 ID 对应、图加载与运行 API。

**作者报告**：指定糖感受刺激测试中，确定性发放时间与 Brian2 一致；随机刺激另比较发放率。此结果针对给定模型与测试，不覆盖所有输入、改动后的可塑模型或具身任务。参见 [核心库原文](https://github.com/satorunet/hae/blob/d4551c26cab1c029b2628dbfaca563fbd2e7bc3d/flybrain/README.md)。

**对我们的候选价值**：稀疏活动调度、数据压缩和跨运行时一致性测试值得研究。其糖刺激下的速度不能与我们的全图训练吞吐直接比较。切换 LIF 还会改变状态、时间单位、输入编码、梯度方法和检查点契约。

## 2. 图与注释导入

阅读 `flybrain/tools/export_graph.py`、`build_mb.py`、`build_groups.py`、`build_compartments.mjs`、`export_positions.py`。

这里将连接表转换成按突触前节点组织的稀疏邻接格式，并建立 KC、MBON、DAN、感觉和下行群组。图结构、群组顺序、可塑边顺序共同决定保存权重的语义。我们使用 `W[post, pre]`，移植时必须明确转置关系。

应记录原始 ID、图哈希、输入输出组、递质符号、静默名单和版本。图的神经元对边数与原始突触接触总数不是同一个量。线上不同任务页面的边数口径有差别，本目录不将其统一成一份图的规模。

## 3. 识字：固定表征与局部读出学习

`juku/reader.mjs` 的主要路径是：图像像素 → 人工映射的嗅觉投射输入 → KC 发放计数 → 分区输入读出 → 字符类别。

源码明确静默不属于所选蘑菇体相关集合的神经元。类别读出使用 `driveByGroup`，并非简单挑选发放最多的 MBON。每次 `look` 会重置动态状态；保存的突触增益与短时神经状态是两种不同的记忆。

`feedback` 在误判后对正确、错误分区施加不同符号的调制。核心增益更新由突触前活动痕迹与调制量共同决定，并限制上下界。“负多巴胺”是有符号软件控制量，不能当成负的生物浓度。

`trainer.mjs` 有独立于训练样本的固定试题、固定评估种子和按类别成绩。每次反复查看固定试题仍可能影响开发选择；因此这种试题更适合作为验证集，最终测试需要另外留出。

在线 `juku/hand.mjs` 支持手写与字体混合、按时间块留出，以及增益平均。按时间块分组能减少连续样本泄漏，但不保证同一书写者完全不跨集合。它不是证明全脑 PPO 权重平均有效的依据。

相关来源：源码索引中的固定版本 `juku/` 文件，以及在线 `juku/hand.mjs`。在线说明与 Git 的差异见 [版本边界](VERIFICATION.md)。

## 4. 人体：三种学习与一个工程身体控制器

**源码入口**：`ningen/README.md`、`web/body-worker.js`、`web/muscles.mjs`、`web/brain-worker.js`、`school/chooser.mjs`、`school/strategies.mjs`、`web/reflex.mjs`、`school/tune.mjs`。

| 层 | 输入与输出 | 学习或控制责任 |
|---|---|---|
| 全脑反应 | 食物、触觉、声音与运动相关人工感觉 → 指定神经群活动 | 是否前进、速度、摄食及部分反射；静默失控相关细胞 |
| 蘑菇体选择器 | 食物类别 → 预设行为方案 | KC→MBON 局部学习；单独建立的子网络实例 |
| 运动局部可塑性 | 下行神经群活动与身体表现 → 调制量 | 指定运动通路输入增益；奖励由工程代码计算 |
| 基本身体控制 | 行为方案、姿态、接触 → 关节力矩 / 肌肉激活 | 静态步态、IK、重心转移、支撑力分配、肌肉分配和补充力矩 |
| 参数搜索 | 多轮身体仿真结果 → 控制配置 | 进化策略，不是生物突触学习 |

身体来自 MyoSim MyoFullBody。公开代码设定 `rootForce: 0`、`rootTorque: 0`，同时使用支撑与平衡求解和额外关节力矩。因此“没有悬空外力支撑”与“纯肌肉自主控制”不可混为一谈。

`body-worker.js` 的 `senses`、`smelling`、`hearing`、`moveSenses` 展示如何从场景状态构造感官量。这些量包含工程映射；不是全部来自逼真的视网膜图像。

`behave`、`GAIT` 与 IK 负责很大一部分运动。作者也明确说明，纯神经转向曾绕圈或越过食物；前进期间的目标方向由身体侧机制辅助。移植时应把这种辅助显式列入基线。

### 局部学习的适用范围

`reflex.mjs` 的调制量结合“结果相对平常的变化”与“该神经群活动相对平常的变化”。源码注释承认：将蘑菇体式规则用于这些下行神经元属于工程借用，没有声称已经找到对应的真实多巴胺回路。

这可以启发小规模行为调节实验，但不能推出它能替代我们的 PPO、解决双足平衡，或自动避免策略崩解。

### 候选筛选

`tune.mjs` 会重评当前最佳设置，并以累积均值比较手设基线。固定版本中，发布标记要求足够的候选评估次数、基线次数与成绩差。该规则是工程门槛，不是统计显著性检验。

可借鉴“展示已验证设置”的分离。不要直接复制其次数和 margin：奖励尺度、随机性与我们不同。

## 5. 在线与服务端的运行链

`ningen/web/app.js` 协调绘制、脑 Worker、身体 Worker 和 school Worker。`school/trial.mjs` 提供服务端试验入口；`school/server.mjs` 汇总试验、记录和等级。阅读时关注 `trial`、`senses`、`frame`、`error` 和回放处理。

在线技术说明指出浏览器脑与身体异步运行，而服务端试验按步同步。这是潜在的部署分布差异，不能仅以“同一代码”推出“相同闭环轨迹”。我们应分别记录控制步、感知延迟、动作保持和仿真实时倍率。

等级按试验次数增加。等级、累计训练量和能力提升是不同指标。群众提交的数据也不能直接充当独立测试。

## 6. 算盘与人工电路

`kakou/graft.mjs` 提供扩展图与构造回路的基础。`hold`、`erase`、`gate`、`sequence` 分别探索状态保持、复位、门控与时序。`soroban/soroban.mjs` 组合规则电路，`bake-soroban.mjs` 生成较小的运行图。

作者解释：数字识别使用学到的读出，算盘运算规则则人工布线；算对后的奖励不训练算盘电路。浏览器运行图也经过裁剪。可借鉴模块构造与裁剪前后的一致性检查，不能把结果记成原连接组学会算术。[作者原理页](https://hae.satoru.net/soroban/)

仅在选定刺激集合上证明输出一致，不足以保证裁剪图对任意未见输入都一致。这是后续采用类似优化时需要补的测试边界。

## 7. LIFE 与可视化真实性

`life/README.md` 区分主雌蝇的实际脑仿真、脚本驱动的雄蝇和规则驱动的后代。神经活动气泡也区分仿真发放与按当前行为标示的相关细胞。该区分对我们的活动面板很有价值。

显示某神经群、显示实际活动、显示因果贡献是三个层次。即使点来自真实胞体坐标，也不能把胞体连线解释为真实轴突形态。

## 阅读优先级

1. 控制与评估：`ningen/README.md` → `body-worker.js` → `tune.mjs` → `trial.mjs`。
2. 局部学习：`brain.c` 可塑部分 → `reader.mjs` → `chooser.mjs` → `reflex.mjs`。
3. 检查点扩展：在线 `migrate_reflex.mjs`，同时看原图布局与长度检查。
4. 推理性能：`brain.c` 活动调度 → `export_graph.py` → `flybrain.js`。
5. 体验与溯源：`app.js` 回放 / trial → `school/server.mjs` → `life/README.md`。

模块可读，不代表可直接移植。特别是 FlyWire 与 MaleCNS 的 ID、群组与 VNC 覆盖不同，需要重新建立映射。
