## 1. 评估与筛选：直接相关，但不要照抄门槛

hae 的参数搜索把候选积累足够评估后再用于网页展示。它提供一个有用的工程分离：正在尝试的状态，不直接等同于对外展示的已验证状态。

我们的最新 CPU 修正已阻止同权重重评登记为新最佳，也已改观测和身体契约。后续 Agent 应先查看已有测试，不要将这份参考误读成这些修复尚未完成。

仍可研究的协议：

1. 冻结一组验证场景、种子、噪声模式与判据。
2. 基线与候选使用成对场景；同时报告个体结果、均值、散布和失败数。
3. 选择用验证集与最终测试集分离；预先限制反复筛选次数。
4. 记录 checkpoint、图、身体、观测、时钟及奖励配置的标识。
5. 同一权重的追加评估扩充证据，不生成一次新的“学习进步”。

这些是候选协议。具体次数、置信区间方法与资源预算需要结合测得的噪声确定。hae 的固定 margin 不能证明我们奖励尺度上的改善。

## 2. 检查点迁移：按语义映射，不只看形状

在线 `migrate_reflex.mjs` 用原图中边的位置把旧可塑增益迁到新通路，检查旧边保留、新增边初始化、布局长度一致。

我们可以借鉴不变量检查，而非复制索引假设。图排序一旦变化，单纯的数组位置可能不再表示同一突触；应绑定图哈希，必要时用明确的前后神经元 ID 作为键。

本项目 47→50 维观测扩展已经存在。后续扩展需要同时保留字段顺序、归一化、单位、动作接口与物理时钟。静态前向等价与长轨迹一致不是相同判据；边际稳定系统可能放大微小数值差异。

## 3. 局部可塑性：先明确要学习什么

hae 展示了三种不同用途：分类读出、预设行为方案选择、局部运动反射调节。它们的奖励来源和输出语义不同。

若未来获准实验，可先选择少量明确动作方案，冻结已有行走策略，测高层选择是否可学习。至少保留随机选择、固定选择、普通小型可训练读出作为对照。

应保存每轮修改的突触范围、增益分布、奖励与轨迹。在线学习开关关闭后需确定性评估，并检查是否遗忘旧行为。不要预设“局部更新一定更稳定”或“多巴胺一定替代反向传播”。

## 4. 身体复杂度：任务难度与生物相似度分开

FFREP 的四足比人形更容易产生目标运动，是作者观察。可提出的解释包括支撑几何、动作维度、奖励密度和神经映射；目前材料无法确定哪一个是主因。

我们已有 G1 与 Yumi，可先用现有身体检查配置、质量与力矩变化带来的差异。新增四足或 416 肌肉人体会扩大模型、控制与验收范围，不属于这次资料整理的实施授权。

hae 的身体控制代码适合查 IK、支撑与肌肉分配。它不提供将我们当前关节策略直接迁成全身肌肉控制的证据。

## 5. 用户可理解的实验界面

可以围绕已有能力组织三个简短工作流：

- **跟随命令**：目标与实际速度、方向、脚触地和跌倒状态同屏显示。
- **扰动恢复**：标出施力时刻、方向和恢复过程，保留失败回合。
- **模型对照**：相同输入回放正常 / 断连，标明模型及身体版本。

此处是交互参考，不要求立即新增 UI。任何文案变动仍同步 zh/en 字典；任何角色资产仍遵守原许可。

若以后加入喂食、等级或用户反馈，应区分参与次数、训练量与独立能力指标。视觉奖励不能被标成已经改变神经权重，除非确有更新并可追踪。

## 6. 性能优化的比较单位

比较 WASM LIF、我们的 GPU 稀疏活动率网络与小网络时，至少注明：

- 实际活跃节点与总节点、神经元对边与突触计数。
- 仿真神经时间、控制频率、批量环境数、是否反向传播。
- 冷启动与稳态、墙钟延迟的中位数 / 尾部、内存峰值。
- 输入分布、数值精度、线程数、硬件与版本。

浏览器下载小、糖刺激推理快、PPO 训练快是三个不同问题。先测瓶颈，再决定压缩、传输、绘制或计算优化。
